# قانون اساسی پروژه (Constitution)

نسخه ۱٫۰ — برای CRM و باشگاه مشتریان راسپینا. این اصول بر هر سلیقه‌ی طراحی و هر فشار زمانی مقدم‌اند.

## اصل ۱ — کاربر غیرحرفه‌ای معیار است

اگر یک کارمند تازه‌کار بدون آموزش نتواند کار روزانه‌اش (ثبت مشتری، پیگیری سفارش، پاسخ تیکت، بررسی امتیاز) را در سه کلیک انجام دهد، طراحی ناقص است. سادگی مسیر، بر تعداد امکانات اولویت دارد.

## اصل ۲ — دسترسی‌پذیری ویژگی است، نه بازبینی

WCAG 2.2 AA کف قابل‌قبول است. کنتراست، صفحه‌کلید، نام قابل دسترس، حالت خطا/خالی/بارگذاری و اندازه‌ی هدف لمسی در همان تغییری ساخته می‌شوند که آن صفحه را می‌سازد. «بعداً درست می‌کنیم» پذیرفته نیست.

## اصل ۳ — امنیت در سرور تصمیم گرفته می‌شود

هر عملیات حساس در PHP دوباره مجوزدهی، اعتبارسنجی و ثبت حسابرسی می‌شود. کلاینت غیرقابل‌اعتماد است. رازها فقط در محیط سرور.

## اصل ۴ — محدودیت هاست، محدودیت محصول است

بدون SSH، بدون Composer روی سرور، بدون daemon. نصب = آپلود فایل + ایمپورت SQL + ویرایش config. هر طرحی که این را نقض کند رد می‌شود، حتی اگر فنی‌تر به نظر برسد.

## اصل ۵ — داده‌ی مشتری حداقلی و قابل‌حسابرسی

فقط داده‌ای جمع کن که برای همان کار لازم است. هر تغییر داده‌ی مشتری ردپای حسابرسی دارد. حذف/ویرایش گسترده نیازمند نقش مدیرعامل است.

## اصل ۶ — تست برای منطق، چشم برای ظاهر

منطق دامنه (امتیاز، سطح، کیف پول، مجوز، اعتبارسنجی، وضعیت تیکت) test-first. تغییر ظاهری با typecheck + build و بازبینی واقعی صفحه تأیید می‌شود، نه با تست تزئینی.

## اصل ۷ — شفافیت در گزارش

هر ادعای «انجام شد» باید به خروجی واقعی وصل باشد. کار تست‌نشده، تست‌نشده گزارش می‌شود.

## دروازه‌های کیفیت (Definition of Done)

- [ ] معیار پذیرش spec برآورده شده و صریح ذکر شده است.
- [ ] `npm run typecheck` پاس.
- [ ] `npm test` پاس (اگر منطق دامنه تغییر کرده، تست جدید دارد).
- [ ] `npm run build` پاس و `public_html/` به‌روز است (اگر فرانت تغییر کرده).
- [ ] تغییر PHP حداقل از نظر syntax بررسی شده؛ محدودیت اجرا گزارش شده.
- [ ] چک‌لیست دسترسی‌پذیری `.ruler/30-accessibility-ux.md` برای صفحه‌ی درگیر مرور شده.
- [ ] هیچ راز/داده‌ی واقعی مشتری در کد، تست یا build نیست.
- [ ] خارج از محدوده‌ی درخواست چیزی اضافه نشده است.
