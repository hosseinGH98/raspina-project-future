# دسترسی‌پذیری و سادگی کاربری — استاندارد اجباری

هدف: هر کارمند راسپینا، حتی با کمترین تجربه‌ی نرم‌افزاری، بتواند بدون آموزش طولانی کار روزانه‌اش را انجام دهد. **WCAG 2.2 AA کف کار است.**

## چک‌لیست هر صفحه/کامپوننت

- **ساختار:** یک `h1` در هر صفحه، سلسله‌مراتب عنوان درست، `main`/`nav`/`header` معنایی، skip-link.
- **صفحه‌کلید:** همه‌ی کنترل‌ها با Tab قابل دسترسی، ترتیب منطقی، `focus-visible` واضح (نه `outline: none` بی‌جایگزین)، Esc برای بستن مودال، focus trap در دیالوگ و بازگشت focus بعد از بستن.
- **نام قابل دسترس:** هر دکمه/آیکن `aria-label` یا متن؛ هر input `label` واقعی (نه placeholder تنها)؛ تصویر محتوایی `alt` و تصویر تزئینی `alt=""`.
- **وضعیت‌ها:** خطا کنار همان فیلد + `aria-invalid` + `aria-describedby`؛ پیام موفقیت/خطا با `role="status"`/`role="alert"`؛ حالت بارگذاری و خالی برای هر لیست/جدول.
- **جدول داده:** `<th scope>` درست، عنوان جدول، امکان استفاده بدون ماوس، در موبایل نمای کارتی به‌جای اسکرول افقی نامفهوم.
- **رنگ و کنتراست:** متن معمولی ≥ 4.5:1، متن بزرگ و آیکن‌های معنادار ≥ 3:1؛ هیچ اطلاعاتی فقط با رنگ منتقل نشود (سطح مشتری، وضعیت تیکت، هشدار).
- **هدف لمسی:** حداقل 24×24 (ترجیح 44×44) و فاصله‌ی کافی؛ فرم‌های موبایل با کیبورد درست (`inputmode`, `autocomplete`, `type`).
- **حرکت:** احترام به `prefers-reduced-motion`; بدون انیمیشن اجباری یا خودکار طولانی.
- **زبان:** فارسی ساده و کوتاه؛ اصطلاح انگلیسی فقط وقتی معادل فارسی ندارد؛ دکمه‌ها فعل‌محور («ثبت سفارش»، نه «ارسال»).
- **اشتباه‌ناپذیری:** تأیید برای عملیات مخرب/غیرقابل‌بازگشت با نام دقیق هدف؛ امکان بازگشت یا undo برای کارهای پرتکرار؛ پیش‌فرض‌های امن.
- **تشخیص و راهنما:** هر بخش توضیح یک‌خطی «این‌جا چه کاری انجام می‌شود»؛ حالت خالی با دعوت به عمل، نه صفحه‌ی خالی.

## قواعد RTL و داده‌ی فارسی

- `dir="rtl"` روی ریشه؛ آیکن‌های جهت‌دار (فلش، بازگشت) باید آینه شوند.
- اعداد و مبالغ با جداکننده‌ی هزارگان و واحد ریال/تومان مشخص؛ تاریخ شمسی؛ موبایل به شکل `09xxxxxxxxx`.
- متن‌های ترکیبی فارسی/لاتین با `dir="auto"` روی مقدارهای کاربر (نام، توضیح، پیام).
- اعداد لاتین داخل RTL با `unicode-bidi: isolate` یا کلاس مناسب، نه با کاراکترهای کنترلی نامرئی.

## معیار پذیرش تغییر UI

1. `npm run typecheck` و `npm run build` پاس.
2. صفحه با صفحه‌کلید به‌تنهایی قابل استفاده باشد (بدون ماوس).
3. هیچ خطای کنسول/شبکه در بارگذاری اولیه.
4. اگر چیزی را ندیدی/تست نکردی، در گزارش بگو «بررسی نشد».
