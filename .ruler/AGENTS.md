# CRM و باشگاه مشتریان راسپینا — قواعد کار ایجنت

> این فایل **تنها منبع حقیقت** برای دستورالعمل ایجنت‌هاست. فایل‌های `AGENTS.md` (ریشه)، `CLAUDE.md` و `.github/copilot-instructions.md` خروجی تولیدشده‌ی `ruler apply` هستند؛ آن‌ها را دستی ویرایش نکنید. هر تغییر قاعده را در `.ruler/` بدهید و `npx @intellectronica/ruler apply --agents agentsmd,claude,copilot,cursor --mcp false --gitignore false` را اجرا کنید.

## محصول در یک نگاه

- پنل CRM ۳۶۰ درجه + باشگاه وفاداری چهارسطحی + پشتیبانی با SLA + کمپین + RMA + کیف پول + کارت هدیه + حسابرسی.
- **کاربر هدف:** مدیرعامل، مدیر شعبه، بازاریابی، پشتیبانی، فروش، تحلیل‌گر. کاربر نهایی ممکن است کاربر حرفه‌ای نرم‌افزار نباشد. **سادگی و دسترسی‌پذیری، ویژگی محصول است نه تزئین.**
- **میزبانی:** هاست اشتراکی لینوکس (cPanel/DirectAdmin) بدون SSH و بدون ترمینال. هر چیزی که به اجرای دستی روی سرور نیاز دارد، قابل قبول نیست.

## پشته و مسیرها

- فرانت: React 19 + TypeScript + Tailwind 4 + Vite 8. بک‌اند: PHP 8.2 بدون فریم‌ورک + MySQL/MariaDB.
- `src/` کد فرانت · `public/` منبع API/SQL/htaccess · `public_html/` **خروجی build** (دستی ویرایش نکنید؛ با `npm run build` ساخته می‌شود) · `docs/` مستندات · `docs/sdd/` مشخصات و برنامه‌ی توسعه.

## قواعد سخت (نقض = کار ناتمام)

1. **امنیت سمت سرور، نه سمت مرورگر.** هر تصمیم مجوز در `public/api/*.php` دوباره بررسی می‌شود. فرانت‌اند فقط نمایش‌دهنده‌ی مجوز است. هیچ‌گاه به `role` یا `permissions` ارسالی از کلاینت اعتماد نکن.
2. **بدون راز در مخزن.** `config.php`، توکن‌ها، کلیدها و `.env` هرگز کامیت یا در `public_html` منتشر نمی‌شوند. فقط `.example`.
3. **هر ورودی نامعتبر است.** اعتبارسنجی و نرمال‌سازی (خصوصاً موبایل ایرانی) هم در مرورگر هم در سرور؛ کوئری‌ها فقط prepared statement؛ خروجی HTML اسکیپ‌شده.
4. **همه‌چیز داخل `public_html`.** هیچ مسیر اجرایی بیرون از آن، هیچ symlink، هیچ وابستگی سیستمی.
5. **بدون شکستن سازگاری هاست اشتراکی:** نه Composer، نه Node روی سرور، نه cron پیچیده، نه daemon. migration باید SQL قابل ایمپورت در phpMyAdmin باشد.
6. **دسترسی‌پذیری WCAG 2.2 AA حداقل استاندارد است** (جزئیات در `30-accessibility-ux.md`).
7. **فارسی و RTL اولویت دارد.** اعداد، تاریخ‌ها، مبالغ و شماره موبایل باید فارسی‌پسند و بدون ابهام باشند.
8. **بدون کامیت/پوش/استقرار بدون درخواست صریح کاربر.**
9. **بدون وابستگی جدید بدون دلیل.** اول با آنچه هست حل کن؛ کتابخانه‌ی جدید = تغییر lockfile + افزایش سطح حمله + هزینه‌ی نگهداری.
10. **کار ناتمام را «تمام» اعلام نکن.** اگر چیزی تست نشد، همان را صریح بگو.

## کیفیت و تحویل

```bash
npm run typecheck   # tsc --noEmit
npm test            # منطق دامنه، مجوزها، اعتبارسنجی
npm run build       # خروجی public_html
npm run verify      # هر سه با هم
```

- منطق دامنه (امتیاز، سطح، کیف پول، مجوز، اعتبارسنجی) **test-first**: تست بنویس، شکست را ببین، بعد پیاده‌سازی. برای تغییرات صرفاً ظاهری تست جدید لازم نیست.
- بعد از تغییر PHP، حداقل syntax را بررسی کن؛ اجرای واقعی PHP/MySQL در این محیط ممکن نیست، پس آن را به‌عنوان محدودیت گزارش کن.
- اگر `public/` را تغییر دادی، `public_html/` را با build دوباره بساز.
